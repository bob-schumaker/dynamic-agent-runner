Status: qualified
Date: 2026-08-30

## Scope and Boundary

This is a local, no-network compatibility characterization for the one pinned
artifact below. It used fixed synthetic messages and a synthetic
`create_record` schema. It did not load model weights, generate text, invoke a
tool, contact an endpoint, or retain rendered transcript content.

The result qualifies only the profile's recorded public template/parser contract
and the omitted DAR `tool_choice` form. It does not claim model competency;
T6.4.5 remains the separately bounded manual competency gate.

- `mlx_lm.load(path_or_hf_repo, tokenizer_config=None, model_config=None,
  adapter_path=None, lazy=False, return_config=False, revision=None)` returns
  `(model, tokenizer)`.
- `mlx_lm.generate(model, tokenizer, prompt, verbose=False, **kwargs)` returns
  `str`.
- `mlx_lm.tokenizer_utils.load(model_path, tokenizer_config_extra=None,
  eos_token_ids=None)` returns `TokenizerWrapper`.
- The selected wrapper has
  `mlx_lm.tool_parsers.json_tools.parse_tool_call(text, tools=None)`, with
  boundaries `<tool_call>` and `</tool_call>`.
- The loaded tokenizer is
  `transformers.models.qwen2.tokenization_qwen2.Qwen2Tokenizer`; its native
  `apply_chat_template` accepts `tools`, `add_generation_prompt`, and forwarded
  keyword arguments.

The parser maps a bounded tool-call payload to a dictionary with exactly the
structural keys `name` and `arguments`. A synthetic
`create_record(title="alpha")` fixture produced result-shape hash
`65d06a856a78c92187524164b8e54ff8aad99f58eea3afc2c75e45b9f3aa984b`.
DAR must still apply its existing strict one-call and JSON normalization.
