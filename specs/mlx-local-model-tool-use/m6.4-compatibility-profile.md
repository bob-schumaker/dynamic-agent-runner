# M6.4.1 Qwen3 MLX Compatibility Profile

Status: incompatible_parser
Date: 2026-08-30

## Scope and Boundary

This is a local, no-network compatibility characterization for the one pinned
artifact below. It used fixed synthetic messages and a synthetic
`create_record` schema. It did not load model weights, generate text, invoke a
tool, contact an endpoint, or retain rendered transcript content.

This evidence records an upstream-parser incompatibility. DAR owns a strict
package parser for the recorded native envelope in `qwen3_mlx_tools.py`; it does
not change this profile's lack of model-competency evidence. The helper accepts
only omitted DAR `tool_choice` and only the pinned configured model identity.

## Public API Characterization

- `mlx_lm.load(path_or_hf_repo, tokenizer_config=None, model_config=None,
  adapter_path=None, lazy=False, return_config=False, revision=None)` returns
  `(model, tokenizer)`.
- `mlx_lm.generate(model, tokenizer, prompt, verbose=False, **kwargs)` returns
  `str`.
- `mlx_lm.tokenizer_utils.load(model_path, tokenizer_config_extra=None,
  eos_token_ids=None)` returns `TokenizerWrapper`.
- The selected wrapper has
  `mlx_lm.tool_parsers.json_tools.parse_tool_call(text, tools=None)`, with
  boundaries `<tool_call>` and `</tool_call>`.
- The loaded tokenizer is
  `transformers.models.qwen2.tokenization_qwen2.Qwen2Tokenizer`; its native
  `apply_chat_template` accepts `tools`, `add_generation_prompt`, and forwarded
  keyword arguments.

The parser maps an extracted JSON payload to a dictionary with exactly the
structural keys `name` and `arguments`. A synthetic
`create_record(title="alpha")` fixture produced result-shape hash
`65d06a856a78c92187524164b8e54ff8aad99f58eea3afc2c75e45b9f3aa984b`.
The template's actual native envelope is not accepted: the same payload wrapped
as `<tool_call>\n…\n</tool_call>` raises `JSONDecodeError`. DAR must not add an
envelope extractor or other custom raw-text parser to bridge that gap.

## Outcome

`incompatible_parser` — the pinned artifact's template/parser pair cannot parse
the complete native tool-call response through the upstream API. DAR's explicit
owned-codec decision supersedes the earlier no-custom-parser constraint: the
package helper may parse exactly this native envelope, but the profile still
does not claim model competency or authorize broader Qwen support.
