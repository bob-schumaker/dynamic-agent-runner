# Project Brief

## Project

- Name: `dynamic-agent-runner`
- Package metadata: Python project declared in `pyproject.toml`
- Current version: `0.1.0`
- Repository root: `/Users/roschuma/Repos/roschuma/dynamic-agent-runner`

## Purpose

- Build a Python library that reads the definition YAML, Mermaid diagram, and
  tool index generated by the agent-development workflow in the
  `clinerules-roschuma` repository.
- Use the official `openai` Python package behind a repository-owned adapter and
  repository-owned tool registry to run an agent workflow from a user prompt and
  return the final result.

## Current Scope

- The repository now includes implemented source under `src/dynamic_agent_runner/`,
  tests under `tests/`, docs under `docs/`, and active SDD artifacts under
  `specs/dynamic-agent-runner/`.
- The runtime supports package-directory workflow loading, async-first execution,
  a repository-owned tool registry, and layered validation/tracing/runtime-policy
  seams.

## Constraints

- Use Python `>=3.13,<3.14.1 || >3.14.1,<3.15` per `pyproject.toml`.
- Local mise configuration selects Python `3.14.6` and an in-project `.venv`.
- Poetry is the package/dependency manager.
- Internal OCI Artifactory Poetry sources are configured in `pyproject.toml`.
- OCI build configuration publishes package artifacts to INDCON release and
  development repositories.
- Runtime/model execution should stay OpenAI-first through the local adapter and
  repository-owned registry; `ocihelper`, `ai-tools-core`, and
  `openai-tools-core` are intentionally not runtime dependencies.
- Input artifacts are expected to come from:
  - `/Users/roschuma/Repos/roschuma/clinerules-roschuma/rules/85-agent-development-workflow.md`
  - `/Users/roschuma/Repos/roschuma/clinerules-roschuma/skills/agent-development-skill/`

## Success Criteria for This Memory Bank

- Future sessions can quickly identify the repository as a Python/Poetry agent
  workflow runner library with implemented runtime surfaces.
- Future sessions know the main runtime direction, environment constraints, and
  where current planning artifacts live.
- Durable product intent stays separate from slice-by-slice implementation
  details.
